# 同步策略与网络重试

用户要求整体网络失败重试，默认 3 次，并调整系统设置“同步执行”名称。本次直接按授权实现，页签改为“同步策略”，包含累计超时与失败重试次数。

- YAML/API 增加 settings.retry_count，省略默认 3、0 关闭、范围 0–10。表示首次之外的额外次数。
- 优先沿用 Rsync 的来源切换，再统一重试整轮；GitHub / Reposync 在同一工作目录重新执行。统一由 runs 控制，不叠加 SDK 请求层无限重试。
- 默认等待 5/10/20 秒，后续封顶 80 秒，等待受同一个任务 context 和累计预算控制。暂停/取消立即打断，继续不重置重试计数与等待期限；持久记录保存计数和 retry_at。
- 仅临时网络、可识别上游错误自动重试；磁盘、权限、认证、配置、证书和校验错误停止。每次 attempt 有独立日志，复用已有增量/验证/Range 能力，只有成功才发布。
- 验证配置默认/关闭/边界/注释写回、三种执行器成功恢复与上限、多源顺序、暂停/取消/重启/超时、GitHub 断流续传、页面保存刷新与响应式。按项目此前批准的 OCR local delegate preview/rule 流程审查全部改动，完成后运行相关测试，记录未验证的 Linux DNF/生产网络条件。
