# GitHub 下载排查与系统设置分类

用户要求：检查已配置 token/proxy 的默认 OpenList 源为何无法下载；系统设置按参考图分类，rsync 与 GitHub Release 单独页签，监听/目录和 TLS 只用 YAML。

采用现有系统字体、蓝色主题和轻边框；新增“同步执行 / rsync / GitHub Release”页签，左右说明与输入分列，窄屏上下排列，支持键盘切换。页面和后端保存都保留固定部署字段；不增加 YAML 字段。

排查使用现有凭证做只读 Release 列表请求，不触发同步、不保存配置；原 HTTPS/HTTP 请求在到达 GitHub 前关闭；同一端口经 SOCKS5 成功返回 API 200，并下载校验一个 121 字节的真实附件。实现固定且脱敏的网络/API 错误诊断和任务日志，禁止自动绕过代理。已按用户授权，通过现有服务 revision 检查与原子写回，仅将当前代理协议修正为 SOCKS5，保留 2001 端口及凭证。

验证采用临时目录、隔离端口及本地代理/附件 fixture：四种代理协议、凭证隔离、重定向、EOF/认证/限流等诊断、固定字段保护和原有续传；浏览器验证分类、草稿保存、凭证状态、固定字段无输入和桌面/手机布局。实现后使用 OCR 本地 delegate 逐文件审查，最终结果记录于 ACCEPTANCE.md。
