# 管理界面与查询性能移植计划

**目标：** 将参考项目已验证的详情组织、按需读取和查询隔离方法适配到 MirrorDock；交付物独立于参考目录。

**设计：** 沿用 Vue、Go 1.27.1、SQLite WAL/FULL、两同步 worker 和既有发布协议。详情展示任务概览、同步阶段、尝试、可折叠日志及配置；活动任务轮询，终态读完日志后停止，隐藏页面停止自动请求。只读查询使用有界读池与取消上下文；最新任务用一次索引查询读取，各 SSE 客户端共用最多一秒的序列化快照。

## 实施步骤

1. `internal/database/database.go`：连接参数随每次连接初始化；列表在同一只读事务读取计数和页，最新任务批量读取。补充写连接被占用时读取仍可完成、取消、重连参数和查询计划回归。
2. `internal/runs/runs.go`、`internal/app/app.go`：管理查询传递请求取消与超时；共享 SSE 快照，避免每客户端重复查询和编码。验证并发读取、失败恢复、过期和等待取消。
3. `web/src/features/runs/`：详情生命周期、统计卡、分区折叠和按需日志。最终日志超过单轮预算时继续分轮读取，不因任务终态漏掉尾部；历史尝试选择与滚动跟随保留。暂停/中断可恢复，保持状态检测。
4. 相关 E2E：终态停止、最终日志补读、折叠/隐藏停止、恢复刷新、错误与重试、桌面/窄屏和键盘焦点。前端格式检查、构建先于嵌入包测试。
5. OCR 审查本轮全部源码差异，排除未修改参考项目；修复问题后运行相关 Go race、vet、E2E。验收结果与未执行项记入 `docs/ACCEPTANCE.md`。
6. 从实际工作区源码生成不含参考目录、用户配置和数据的临时副本，验证独立 Web/Go 构建。

本轮不改变 YAML 真源、公开下载热路径、运行状态持久化顺序。统计缓存、批量操作 API、目录扫描并发留待本轮测量后单独评估，避免同时引入多个一致性边界。
