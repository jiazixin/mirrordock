# Rsync 与 GitHub Release 运行分析

用户要求在侧栏增加分析，选择有价值的指标与适当图表；延续既有 MirrorDock 视觉和配置协议。

实现范围：侧栏“分析”分组下独立 Rsync / GitHub Release 页面，7/30/90 天（含今天）和同步源筛选。成功率、运行次数、平均累计执行耗时、成功任务处理量为公共指标；趋势可切换次数堆叠柱图、处理量折线、耗时折线，结果环图、失败原因条形图、前 20 源排行。Rsync 展示来源尝试、失败尝试、备用源最终成功与自动重试任务；GitHub 展示已验证资产、新增/续传和完整复用以及自动重试。

统计口径：按任务创建日期归入启动时区；成功率分母为成功/失败/超时/中断，排除取消及未结束；平均耗时为已开始的上述任务累计执行时间，排队/暂停不计入。文件/资产/字节仅累计成功任务最后快照，不伪称真实网络字节，不推算未知失败文件、Release 数量或节省流量。GitHub 复用是完成数的子集；跨运行同一资产可以重复累计。

实现顺序：

1. `internal/runs/analytics.go` 流式读取 SQL 聚合投影，日序列 7/30/90 项、源排行 20 项、错误码 8 项，不向 Go 载入完整配置或读取日志。按时间索引覆盖全部记录，原始日志清理不影响分析。
2. `internal/database` 建立创建时间索引，单连接只读池隔离写连接，WAL 一致事务读取三组数据；接口请求最长 5 秒。
3. `internal/app/analytics.go` 增加受现有 Cookie 鉴权的 GET `/api/analytics`；参数校验、泛化错误、上下文取消，不进入公开下载处理链。
4. `web/src/features/analytics/` 实现页面与响应式 SVG 趋势；无新增 npm 依赖，筛选取消过期请求、离开停止请求，手动刷新，无新轮询。
5. 临时 SQLite 测试全历史、筛选、午夜/小数秒/DST、结果口径、参数与鉴权、只读及写入隔离；Chromium 使用临时服务和合成图表数据检查交互/空错/手机。用 5000 合成记录测量查询开销。
6. OCR 本地 preview/rule 和当前 Codex 全部源码审查，覆盖默认排除测试；修复确认问题后构建 Web、Go race/vet、浏览器回归，结果写入 ACCEPTANCE。

未授权子代理、外部消息、推送或发布；用户数据和凭证不用于测试。
