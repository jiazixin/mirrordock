# 下载、日志清理与目标 Linux 验收实施计划

目标：降低公开下载的路径解析和分配开销，避免历史日志清理阻塞整个运行引擎，并在用户提供的 AlmaLinux 10.2 x86_64 虚拟机执行最终版本验收。

## 方案与约束

采用有界受限根 LRU，缓存最多 32 个代，低 FD 环境进一步缩小到预留额度的四分之一。一个镜像锚点固定打开；请求仅在取得文件期间借用代根，文件与路由引用保持原生命周期。缓存满且所有根被借用时使用瞬态根，计入现有请求 FD 预算。相较只缓存锚点，它能消除热请求的两次根打开；相较永久保存所有发布根，它不随旧代增长。回收与 Close 释放根，继续使用真实文件与 ReaderFrom/sendfile。

元数据缓存改用结构键，命中不再格式化 ETag 键；Content-Disposition 随不可变元数据缓存。不能缓存可变正文、绕过 os.Root 或引入正文哈希/数据库查询。

日志清理使用有上界的 ID 游标，每页 100 个终态记录，不使用 OFFSET/全表 count。独立清理互斥，逐任务设置清理租约；文件删除/落库在 Engine.mu 外进行。相同任务的动作等待该租约，其他任务正常运行。日志打开使用独立短锁，已打开的导出继续读取原长度。请求取消/服务退出终止后续批次；删除或保存失败保留错误且可以重试，记录和结果摘要不删除。

历史原始日志继续遵守页面手动清理协议，不能自动删除用户日志或修改外部备份；配置中的旧鉴权 URL 应替换为公开地址，泄露凭据须由所有者轮换。数据库快照迁移保持现有行为。
